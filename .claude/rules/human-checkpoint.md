# 人とのすり合わせと報告の出し方

目的は、人の認知負荷を下げることと、人と AI の認識のずれを作業が進む前に止めること。
文章で長く尋ねたり報告したりせず、人が返すものに合う形で出す。

## すり合わせ (作る前・分岐点)

- 案を並べないと決められない (プロンプト・文面・デザイン・命名) → run-bestofn
- 1 つの案や成果物に、指摘・承認・差戻しをもらう (実装前の方針確認、長文への指摘) → akapen
- 作った画面・文書・図の上に描いて直してもらう → tenaoshi
- 複数の項目にそれぞれ判定を付けてもらう (未決が 4 つ以上、残すか消すか) → shiwake

仕様と受け入れ条件が決まっていて、テストで正否が分かる作業では確認を挟まない。

## 報告 (作った後)

- 短く言える結果は文章で返す
- 構造・流れ・前後の比較・複数の関係など、図や表で見たほうが早い内容は HTML 1 枚で見せる
  (Orca のチャット内なら orca-chat-visuals)
- HTML にした時も、結論は文章で 1〜2 行添える
